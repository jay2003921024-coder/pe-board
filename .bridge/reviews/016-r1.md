## 涵蓋的驗收條件檢查

### AC-14（觸控命中範圍 ≥44×44 CSS px）

- `js/ui/board.js:12-19` 新增 `pxToSvg()`：優先用 `board.getScreenCTM().a` 的倒數換算 1 CSS px 對應的 SVG viewBox 單位（涵蓋 `preserveAspectRatio` 留白），沒有 CTM 時退回 `viewW / boundingRect.width`。
- `handleR()`（`board.js:21-25`）：觸控時回傳 `Math.max(r, 22 * k)`，其中 `k = pxToSvg()`。因為 `ctm.a` 本身就是「1 SVG 單位 → 多少 CSS px」，`hr * ctm.a = 22 * k * ctm.a = 22`（CSS px），半徑固定 22px、直徑固定 44px，不受畫面縮放或場地比例影響。數學上與驗收報告建議修法一致，推導正確。
- `overlay()` 內把手（`board.js:48-56`）維持外層透明命中圓 `r=hr`、內層可見圓 `r=vr=hr/2`（觸控時），與任務 015「可見圓縮小一半、可點擊範圍不變」的既有要求相容。
- 推斷：此修法可解決報告中 iPad 橫向 24.99px、直向 20.15px 皆未達 44px 的問題；未實機／CDP 覆測複驗，但換算邏輯本身無誤。

### AC-15（捲動/平移/慣性滑行期間不整個重繪 `board.innerHTML`）

- `js/ui/board.js:69-82` 把「更新 viewBox」拆成獨立的 `renderView()`，`renderBoard()` 內部呼叫 `renderView()` 再重建 `innerHTML`，並在 `initBoard()` 掛上 `hooks.renderView`（`board.js:85-87`），`state.js:23-24` 同步補上 `renderView: noop` 預設值，掛勾機制正確。
- `editor.js` 中確認下列各處改為呼叫 `renderView()` 而非 `renderBoard()`：
  - `inertiaApplyField`（`editor.js:70-75`）
  - `panMove` 放大分支（`editor.js:271-275`）
  - `pinchMove` 在無選取物件時（`editor.js:173`：`if (selIds().length) hooks.renderBoard(); else hooks.renderView();`）
- `onPointerDown` 進入 `pan` 分支（`editor.js:243-248`）：記錄 `prevTouch`／`hadSel`，只有「按下前有選取物件」或「觸控狀態剛切換」才呼叫 `renderBoard()+renderProps()`，其餘情況（最常見的空白處單指捲動）完全不重繪，直接解決報告中 `e.target` 在手勢啟動瞬間脫離 DOM 導致 `pointercancel` 的問題。
- 這一組改動精準對應報告列出的 5 個問題點（`inertiaApplyField`、`pinchMove`、`onPointerDown` pan 分支、`panMove`、`renderBoard` 本身），且修法與報告建議幾乎逐字一致。

### AC-18（雙指原地縮放飄移／停住再放開仍滑行）

- **問題 A（縮放中心飄移）**：`pinchMove()`（`editor.js:176-180`）改用兩指中心點 `centerClient` 相對上一幀 `drag.lastCenter` 的真實位移，透過 `getScreenCTM().inverse()` 換算成場地單位後再丟給 `trackVelocity`，不再用 `prevX - state.view.x`（viewBox 左上角因縮放而改變的座標差）。原地縮放時兩指中心不動 → `dxCenter/dyCenter = 0` → 不會誤觸發慣性滑行。推導正確，與報告根因分析相符。
- **問題 A 附帶修法（雙指同幀速度暴衝）**：`trackVelocity()`（`editor.js:30-43`）改成先把 `dx/dy` 累加到 `drag.accDx/accDy`，`dt < 8ms` 時不計算瞬時速度，避免雙指觸控同幀兩次 `pointermove` 因極小 `dt` 讓速度暴衝。邏輯正確；`drag.t === undefined` 時提早 `return`（不累積丟棄位移、只記錄時間起點），之後每次 `dt>=8` 才清空累加值，沒有位移遺失或重複計算的問題。
- **問題 B（停住再放開仍滑行）**：`startInertiaFromDrag()`（`editor.js:78-83`）新增 `!drag.lastMoveAt` 與 `performance.now() - drag.lastMoveAt > 80` 兩個提早返回條件。`drag.lastMoveAt` 只在 `trackVelocity` 真正算出瞬時速度（`dt>=8`）時更新（`editor.js:42`），語意正確：手指停住超過 80ms 再放開時，`lastMoveAt` 會停留在停住前的時間點，差值超過 80ms 就不啟動慣性滑行。

未發現這三組修法有邏輯錯誤或與 AC 要求不符之處。
