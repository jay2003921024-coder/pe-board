## 非阻擋建議（不影響判定）

1. `firestore.rules:37`：`authorName` 由客戶端任意填寫（create 與 update 都可改），規則未與 `request.auth.token.name` 比對，作者可冒用他人名稱顯示。SPEC 未要求防冒名；若在意，可在 update 時要求 `authorName` 不變，或 create 時比對 token name（注意 token 可能沒有 name）。
2. `firestore.rules:57-60`：`users/{uid}.folders` 只檢查是 list 且 ≤ 500 項，未檢查元素型別與長度。僅本人可寫，風險低；可在 `planFolderMerge` 已過濾非字串的前提下維持現狀。
3. `js/store/firebase.js:48-50`：若 `initializeApp` 成功但後續步驟失敗，重試時會再次呼叫 `connectAuthEmulator`（僅 emulator 模式）而拋錯→仍是 offline，不會冒出錯誤，只是無法自動恢復。實務上幾乎不會發生。
4. 交接筆記已提到：離線時 publish 逾時回 `{offline:true}` 但寫入可能稍後送出，可能產生重複；008 的 UI 應提示使用者重新整理確認。
