## 交接筆記

修正驗收報告 `.bridge/reviews/verify-r5.md` 中三項失敗（AC-14、AC-15、AC-18），皆依報告建議修法實作，與報告描述的根因一致：

1. **AC-14（`js/ui/board.js`）**：`handleR()` 原本把觸控最小半徑寫死 `22`（SVG viewBox 單位），在 iPad 上換算成 CSS px 只有 20～25px。改為新增 `pxToSvg()`：優先用 `board.getScreenCTM().a` 的倒數換算「1 CSS px → 多少 SVG 單位」（含 `preserveAspectRatio` 留白，沒有 CTM 時退回 `viewW / boundingRect.width`），`handleR()` 回傳的半徑一律先乘上 `pxToSvg()` 再比較，讓觸控命中圓在任意 iPad 直/橫向與場地比例下的螢幕尺寸恆為 `44×44 CSS px` 以上。`overlay()` 裡可見圓 `vr = hr/2` 的邏輯不變（已是正確比例），自動跟著放大。

2. **AC-15（`js/ui/board.js` + `js/ui/editor.js` + `js/ui/state.js`）**：新增只更新 `<svg viewBox>`、不重寫 `board.innerHTML` 的 `renderView()`（board.js），掛進 `hooks.renderView`（state.js 新增 hook 欄位、board.js `initBoard()` 掛上）。`editor.js` 改動：
   - `panMove()`（放大時平移）、`inertiaApplyField()`（慣性滑行）：`hooks.renderBoard()` → `hooks.renderView()`，捲動/滑行期間零次重寫 DOM。
   - `pinchMove()`：只有目前有選取物件時才 `renderBoard()`，否則 `renderView()`。
   - `onPointerDown()` 進入 `pan` 分支（觸控單指在空白處按下）：原本無條件 `renderBoard()+renderProps()` 會讓 `e.target` 在手勢啟動瞬間脫離 DOM；改成只有「按下前有選取物件」或「觸控狀態剛切換」時才重繪，其餘情況（最常見：空白處、touch 狀態未變）完全不重繪。

3. **AC-18（`js/ui/editor.js`）**：
   - 問題 A（原地縮放放開後飄移）：`pinchMove()` 原本用 `prevX - state.view.x`（viewBox 左上角因縮放改變的座標差）當平移速度；改成用「兩指中心點 `centerClient` 相對上一幀 `drag.lastCenter` 的實際位移」經 `getScreenCTM().inverse()` 換算成場地單位，原地縮放時中心點不動、速度即為 0，不再誤觸發慣性飄移。
   - 問題 A 附帶修法：`trackVelocity()` 改成先把 `dx/dy` 累加到 `drag.accDx/accDy`，`dt < 8ms` 時不計算瞬時速度（避免雙指同幀兩次 `pointermove` 因極小 `dt` 讓速度暴衝），並記錄 `drag.lastMoveAt`。
   - 問題 B（停住再放開仍滑行）：`startInertiaFromDrag()` 新增檢查，若 `performance.now() - drag.lastMoveAt > 80`（最後一次有效移動距放開已超過 80ms，代表手指已停住）則不啟動慣性滑行。

### 驗證方式

- `npm test`：137 項全數通過（含既有 viewport/history 等單元測試），未改動任何 `js/core/**` 檔案，golden test 與結構測試（檔案 ≤400 行、`core` 不碰 DOM）不受影響。
- AC-14/15/18 屬於觸控手勢與實機尺寸的行為，`js/core` 沒有可直接單元測試的純函式變動點（`editor.js`/`board.js` 屬 UI 層，依既有測試策略不寫 jsdom 測試），需要靠 E2E（Headless Chrome CDP 觸控事件＋`MutationObserver`）或實機覆測驗收報告中對應的量測方式：
  - AC-14：量測 `[data-handle]` 外層命中圓 `getBoundingClientRect()` 在 iPad 橫/直向下是否 ≥ 44×44 CSS px。
  - AC-15：掛 `MutationObserver({childList:true})` 在 `#board`，確認單指捲動（未選取時）與放大後單指平移／慣性滑行／雙指縮放（無選取時）期間 `board.innerHTML` 不再被整個銷毀重建。
  - AC-18：重現報告中「原地雙指縮放放開」與「拖曳後停頓 350ms 再放開」兩個情境，確認縮放中心不再飄移、停頓後放開不再觸發滑行。

### 已知限制

- `pxToSvg()` 的 `getScreenCTM()` 路徑需要 `#board` 已掛載在真實 DOM 且有版面（有寬高）才會準確；若在極端情況下 `getScreenCTM()` 回傳 `null`（例如元素尚未上版面），會退回 `viewW / boundingRect.width` 的近似值，與原本桌機模式的計算方式相同。
- 本輪修正沒有新增自動化測試覆蓋這三項 AC（維持 SPEC/PLAN 既定的「DOM 互動不寫 jsdom 測試，靠 REGRESSION/E2E 把關」原則），仍需 antigravity_ide 以同一套觸控事件與 `MutationObserver` 量測方式重新驗收確認數據達標。
