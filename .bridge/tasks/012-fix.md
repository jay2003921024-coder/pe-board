## 目標

使用者看了 demo 後的回饋：

> 1.雙指放大時畫面會亂跑：放大時沒有以手指捏合的位置為中心。2.手指放在戰術板上往下滑，頁面不會捲動：原因是畫布設了「觸控不捲動頁面」，這是為了 AC-15 防止畫圖時誤觸捲動。所以要改成「怎樣算畫圖、怎樣算捲動」的規則，例如在空白處用兩指滑動就捲動頁面，或縮小畫布的高度。

## 交接筆記

### 做了什麼

**1. 雙指縮放亂跑（`js/ui/editor.js` 的 `pinchMove`）**

根因：原本每一幀都用 `board.getScreenCTM()` 把兩指中心點換算成場地座標，再拿「這一幀的 center」減「上一幀存的 lastCenter」來平移。問題是 `getScreenCTM()` 讀的是「當下 DOM 實際的 viewBox」，而 `renderBoard()` 在每一幀結尾就把 `state.view`（也就是 viewBox）更新掉了——所以下一幀算出來的 `center` 用的是「新 viewBox」，但存著的 `lastCenter` 是用「舊 viewBox」算出來的，兩者座標系不一致，縮放幅度越大、手指移動越快，誤差越明顯，表現就是「畫面亂跑、不是以兩指中間為中心」。

修法：改成每一幀只取一次 `board.getBoundingClientRect()` 與 `state.view`（同一個快照），不再呼叫 `getScreenCTM()`：
- 先用「上一幀兩指中心的螢幕座標」＋「這一幀開始前的 view／rect」反推出對應的場地座標 `anchor`（也就是上一幀兩指中間壓著的那個點）。
- 用這一幀的兩指距離比例算出新的縮放倍率與新的 `w/h`。
- 讓 `anchor` 這個場地座標點，移到「這一幀」兩指中心在螢幕上的相對位置（`rx, ry`），算出新的 `view.x/y`，再 `clampView` 夾回邊界。

這樣整個計算只依賴單一時間點的 view／rect 快照，不會再跨幀混用不同的座標系。`zoomAt`／`panBy` 兩個純函式本身沒問題（換算邏輯對、單元測試都通過），改成不在 pinch 手勢裡使用它們、自行做等價但一致的計算；`ptRaw`（唯一呼叫處）已移除。

**2. 畫布上滑動頁面不會捲動**

根因：`#board` 與 `.canvas-wrap` 原本是 `touch-action:none`（005 任務為了 AC-15「不會誤觸成捲動頁面或放大頁面」而加），所以在畫布上不管想做什麼手勢，瀏覽器原生的捲動一律被擋掉。

修法（區分「怎樣算畫圖、怎樣算捲動」）：
- CSS 改成 `touch-action:pan-y`（`css/layout.css`、`css/touch.css`），預設放行垂直捲動。
- 新增 `board` 的原生 `touchmove`（`{passive:false}`）事件：只要 `state.drag` 有值（放置物件、拖物件、拖線條端點/控制點、拖字級把手、雙指縮放）就 `preventDefault()`，擋掉原生捲動——這些正是 AC-15 列出的手勢，一律維持原本「不會誤觸捲動」的行為。
- 唯一改變的情況：**觸控、非多選模式、點在空白處**。原本這裡一定會開始「框選」（`state.drag = {kind:'box',...}`），導致每次滑動都被判定成畫圖手勢而擋下捲動。AC-15 只要求「點空白處取消選取」要能用，並沒有要求空白處拖曳框選在觸控上一定要能用；框選＝多選的手勢是 005 任務特別描述的「多選模式」才需要的行為（`.bridge/tasks/005-touch-interaction.md`：「多選模式...在空白處拖曳＝框選並保留既有選取」）。所以改成：觸控且非多選模式時，點空白處只取消選取、不設定 `state.drag`，於是 `touchmove` 不會攔截，手指滑動會變成原生頁面捲動；多選模式（`state.ui.multi`）下空白處拖曳框選的行為完全不變。

### 怎麼驗證

- `npm test`：128 項單元測試全數通過（0 失敗），`zoomAt`/`panBy`/`clampView` 相關測試不受影響（這幾個函式本身沒改，只是 `pinchMove` 改成不呼叫它們、自行做等價計算）。
- 讀碼覆查 `onPointerDown`：AC-15 列出的四種手勢（點選工具後點畫布放置物件、拖曳物件、拖曳線條端點與控制點、點空白處取消選取）全部仍然會設定 `state.drag`（或在「取消選取」情境下直接 `return`，沒有開始框選，但也沒有改變「點一下取消選取」本身的行為），`touchmove` 的 `preventDefault` 邏輯涵蓋齊全。
- 因為沒有實體 iPad／瀏覽器環境可用，**雙指縮放是否真的不再亂跑、空白處滑動是否真的能捲動頁面，仍需要在實機或瀏覽器觸控模擬下人工覆核**（這點應該在下一輪端到端驗收或檢查點 3 的實機試用時確認）。

### 已知限制

- 多選模式下，空白處拖曳框選的手勢保持不變，若使用者在多選模式下滑動畫布空白處，仍然不會捲動頁面（這是刻意保留的既有行為，不在本次回饋範圍內）。
- `touch-action:pan-y` 只放行垂直捲動；若未來有「水平也要能捲動」的需求需另外處理（目前 AC-14 要求「沒有水平捲軸」，所以沒有開放 `pan-x`）。
