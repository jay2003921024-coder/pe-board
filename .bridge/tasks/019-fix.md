使用者看了 demo 後的回饋：

> iPad 實機：手指碰到圖板時捲動網頁，畫面一直閃、跳動，拖曳物件也卡（018 更糟，已還原 f569ac8）。verify-r8 測的是已還原的程式，作廢。改成「按在空白處交給瀏覽器原生捲動」，詳見 DECISIONS 2026-11-16

## 目標

在 iPad 實機上，手指從圖板空白處開始滑動時，網頁要像一般網頁一樣順暢捲動，**不閃、不跳**；拖曳物件的手感回到不卡頓。

### 背景（為什麼要改設計，而不是繼續補）

- 使用者 2026-11-03 在 iPad 實機回報：手指碰到圖板時捲動網頁，畫面會一直閃、跳動（任務 017 的版本就有一點，018 更嚴重），拖曳物件也變卡，所以還原了 018（commit `f569ac8`）。
- `.bridge/reviews/verify-r8.md` 的 PASS 是在 headless Chrome 上測 018 的程式，那些程式已經還原，**這份報告作廢**。headless Chrome 模擬的觸控抓不到 iPad Safari 的問題。
- 根本原因：`#board`／`.canvas-wrap` 設了 `touch-action:none`，碰到圖板時的頁面捲動全部由 JS 模擬（`window.scrollBy` 加自製慣性，見 `js/ui/editor.js` 的 `panMove`、`inertiaApplyScroll`、`startInertiaFromDrag`）。JS 捲動會讓 Safari 網址列伸縮，觸發 resize 和重繪，就閃了；每幀的事件處理也拖慢了物件拖曳。014～018 都在補這套模擬，越補越糟。
- 014 當初改成全部自己接管，是因為「先讓瀏覽器原生捲動，兩指落下後才改成 JS 縮放」，兩邊搶手勢造成畫面亂跑。這次的設計要避開這個問題：**手勢的主人在手指按下的那一刻就決定，之後不再轉手**。

## 涵蓋的驗收條件

- AC-15（必要）、AC-18（加分）；不可讓 AC-14、AC-16、AC-17 退步

## 介面契約

### 1. 純函式（`js/core/gesture.js`，新檔，不碰 DOM）

```js
// 手指按下的那一刻決定這個手勢交給誰。
// 回傳 'native'：交給瀏覽器原生捲動，程式不處理這個手勢；
// 回傳 'app'：程式接手（放置、拖曳、框選、縮放、平移），必須擋掉原生行為。
export function touchOwner({ tool, multi, zoomed, onTarget, touchCount, animating })
```

規則（照順序判斷）：

| 條件 | 回傳 |
|---|---|
| `touchCount >= 2`（第二指落下） | `'app'` |
| `animating`（正在播放動畫，按下＝停止播放） | `'app'` |
| `onTarget`（按到物件 `[data-id]` 或把手 `[data-handle]`） | `'app'` |
| `tool !== 'select'`（任何放置／畫線工具） | `'app'` |
| `multi`（多選模式，空白處拖曳＝框選） | `'app'` |
| `zoomed`（畫布已放大，空白處拖曳＝平移畫布） | `'app'` |
| 其他（選取工具、非多選、未放大、按在空白處） | `'native'` |

選取工具是 `state.ui.tool === 'select'`（`js/ui/state.js:11`）。

另外一個純函式，給 CSS class 切換用：

```js
// 現在的狀態下，「按在空白處」會不會交給原生捲動。用來決定 #board 的 touch-action。
export function blankIsNative({ tool, multi, zoomed, animating })
```

### 2. DOM 接線（`js/ui/editor.js`、`css/touch.css`）

- `css/touch.css`：`.canvas-wrap{touch-action:none}` 改成 `touch-action:pan-x pan-y`；新增 `#board.app-gesture{touch-action:none}`（以及 `.canvas-wrap` 若有需要也一起）。`-webkit-touch-callout:none`、`user-select:none` 保留。
- `#board` 的 class `app-gesture`：`blankIsNative(...)` 為 false 時加上。工具切換、多選切換、縮放改變、開始／停止播放時都要更新（`js/ui/board.js:81` 的 `renderBoard()` 已經在切換 `placing` class，可以在同一處切換；縮放只呼叫 `renderView()` 的路徑也要更新）。
- 新增 `board.addEventListener('touchstart', onTouchStart, { passive: false })`：用 `touchOwner(...)` 判斷，`'app'` 就 `e.preventDefault()`；`'native'` 就什麼都不做。`touchCount` 用 `e.touches.length`，`onTarget` 用 `e.target.closest('[data-id],[data-handle]')`。
- `onPointerDown` 的「觸控＋空白處＋非多選」分支：
  - 已放大：跟現在一樣建立 `kind:'pan'`，只平移 viewBox（`drag.space = 'field'`）。
  - 未放大：**不建立 drag、不呼叫 `renderBoard()`**，記下 `state.pendingTap = { id: e.pointerId, x, y, hadSel }` 就 return。
  - 這一指 `pointerup` 時，若 `pendingTap` 還在且位移 < 8px，才 `clearSel()`、`renderBoard()`、`renderProps()`（點空白處取消選取，AC-15）。`pointercancel`（原生捲動接手時瀏覽器會送）只清掉 `pendingTap`，不取消選取。
- `onTouchMove`：維持「有 `state.drag` 才 `preventDefault()`」。
- `js/ui/board.js:88` 的 resize 監聽：改成只有 `#board` 的寬度真的改變時才重繪（Safari 網址列伸縮只改高度，不該重繪）。

### 3. 要刪掉的程式

- `panMove` 裡 `window.scrollBy` 的分支（未放大不會再進 `panMove`）。
- `scrollMax`、`inertiaApplyScroll`，以及 `startInertiaFromDrag` 裡 `drag.space === 'client'` 的分支和貼邊判斷。
- 放大後平移畫布的慣性（`inertiaApplyField`）保留。
- 刪完後確認沒有其他地方還在用這些函式；`js/core/viewport.js` 裡變成沒人用的匯出與對應測試一起刪掉。

## 驗收方式（重要）

- AC-14～AC-18 **必須由使用者在 iPad 實機上確認**，headless Chrome 的結果只能當參考。使用者要試的項目：
  1. 手指從圖板空白處上下滑動 → 網頁順暢捲動，有原生慣性，畫面不閃不跳
  2. 拖曳物件、線條端點、控制點 → 跟手、不卡、不會變成捲動
  3. 用放置工具點圖板 → 放下物件，不會捲動
  4. 點空白處 → 取消選取；從空白處滑動捲動 → 不會取消選取
  5. 雙指捏合 → 畫布縮放；放大後單指拖曳 → 平移畫布；「縮放 100%」→ 復原
- 已知風險：未放大時，如果第一指已經開始捲動網頁，第二指才放上去，這次會繼續捲動，不會切換成縮放。兩指同時放上去才會縮放。請在交接筆記寫明實際行為。

**已知限制（iPad 實測時對照）**
- 未放大時，第一指已經開始原生捲動、第二指才放上去：瀏覽器已送 `pointercancel` 移除第一指，不會切換成縮放，會繼續捲動。兩指幾乎同時放上去才會縮放。（從程式推斷，未實測）
