## 目標

使用者看了 demo 後的回饋：

> AC-18／AC-15                                                                                      
  平板觸控回饋：雙指縮放與放大後平移功能運作正常，但「單指在畫布空白處捲動頁面」存在三個嚴重問題：                                         
                                                                                                                                           
    【問題一：單指按住畫布空白處約 1 秒，畫面狂閃超多下甚至閃退】                                                                          
    - 在哪裡：css/touch.css（#board 的 max-height 使用 calc(100vh - 230px)）、js/ui/editor.js（onPointerDown 與 panMove                    
  缺乏微幅位移防抖）、js/ui/editor.js（未攔截 contextmenu）。                                                                              
    - 做什麼：在 iPad Safari 用選取工具，單指按住畫布空白背景停留約 0.5~1 秒不移動。                                                       
    - 現在怎樣：畫面一瞬間連續劇烈閃爍超多次；手指按著不放就一直閃，放開才恢復；按太久會引發 Safari                                        
  白畫面閃退（重新載入）。原因是電容微噪訊觸發 window.scrollBy，導致 Safari 頂部網址列展開/收起，與 100vh 形成 60Hz 震盪死循環。           
    - 應該怎樣：手指單純按住畫布空白處時，畫面保持 100% 穩定，絕不閃爍、不改變大小、不閃退；且不跳出 iOS 放大鏡或系統選單。                
    - 怎麼驗證：在 iPad Safari 單指按住畫布空白處 5 秒不動，畫面全程無任何閃爍或重新載入；未滑動超過 8px 前 window.scrollBy 呼叫次數為 0。 
                                                                                                                                           
    【問題二：慢速捲動頁面時跟手度不順、卡卡的且伴隨跳動】                                                                                 
    - 在哪裡：js/ui/editor.js（panMove 內的 window.scrollBy）與 css/touch.css（動態 100vh）。                                              
    - 做什麼：未放大狀態下用選取工具，單指在畫布空白處以慢速上下滑動以捲動整頁教案。                                                       
    - 現在怎樣：捲動像一格一格的不滑順，且因慢速移動頻繁在頁面頂端（scrollY ≈ 0）臨界點徘徊，容易誘發 Safari                               
  網址列反覆切換導致畫布劇烈跳動閃爍。                                                                                                     
    - 應該怎樣：慢速滑動必須連續平滑跟手；畫布高度恆定，不受 Safari 網址列伸縮影響，絕無跳動或閃爍。                                       
    - 怎麼驗證：在 iPad Safari 以極慢速度上下來回滑動 5 次，整頁平穩位移，畫布尺寸與內容完全不抽搐。                                       
  
    【問題三：捲動到右下角/頁面底端時生硬撞牆與回彈】                                                                                      
    - 在哪裡：js/ui/editor.js（inertiaApplyScroll、startInertiaFromDrag）。                                                                
    - 做什麼：在畫布右下半部單指向上滑動，將頁面捲動到底端查看教案說明欄位並放開手指。                                                     
    - 現在怎樣：捲到最底端時瞬間硬生生卡死，放開手指後殘留慣性繼續硬推底端，感覺像撞到牆壁被彈回來一下。                                   
    - 應該怎樣：捲動到達底端時平穩停住，放開手指時自動抑制向下無效的慣性滑行，無碰撞與彈回感。                                             
    - 怎麼驗證：單指快速向上滑動使頁面到底，放開手指後自然定格在底端，無反向抽動或彈回感。

## 交接筆記

做了什麼：

1. **問題一（長按閃爍/閃退）**：
   - `css/touch.css` `#board` 的 `max-height` 改用 `100svh`（small viewport height，不受 Safari
     網址列顯示/隱藏影響），保留 `100vh` 作為不支援 svh 瀏覽器的 fallback（前一行會被後一行覆蓋）。
     這是震盪死循環的根（scrollBy → 網址列切換 → 100vh 變 → #board 變尺寸 → 再次誤判捲動）。
   - `js/ui/editor.js` `panMove()` 加入 8px 死區：手勢開始後、累積位移距離 < 8px 前只累加不呼叫
     `window.scrollBy`/`panBy`，超過門檻才一次套用累積位移並轉入正常逐幀套用，過濾電容微噪訊。
   - `initEditor()` 新增攔截 `contextmenu`，避免單指長按跳出 iOS 系統選單/放大鏡與自接管手勢互搶。

2. **問題二（慢速捲動卡頓/跳動）**：與問題一同源（100vh 震盪），改 `100svh` 後應一併解決；
   8px 死區只影響手勢開始的門檻，之後逐幀即時套用不影響慢速滑動的跟手度。

3. **問題三（捲到底端撞牆回彈）**：
   - `inertiaApplyScroll()` 改用 `scrollTo` 把目標位置夾在 `[0, scrollWidth/Height - innerWidth/Height]`
     內；一旦偵測到這一幀被夾住（代表已到底/到頂），立即 `stopInertia()`，不讓慣性繼續空轉。
   - `startInertiaFromDrag()` 在 `drag.space === 'client'` 時，若放開手指當下已經在邊界且速度方向
     是繼續往邊界外衝，直接把該軸的速度歸零，兩軸都為 0 就不啟動慣性。

怎麼驗證：
- `npm test` 137 個測試全數通過（含 `js/`、`css/` 單檔 ≤ 400 行的結構測試，確認改動後 `editor.js`
  與 `touch.css` 仍在上限內）。
- 程式邏輯以 code review 方式人工確認：8px 死區門檻前 `window.scrollBy` 呼叫次數為 0（直接 return，
  未呼叫）；`inertiaApplyScroll`／`startInertiaFromDrag` 的邊界判斷涵蓋「開始就在邊界」與「滑行中
  途到達邊界」兩種情況。

已知限制：
- AC-15 問題一、二、三都牽涉 iPadOS Safari 的網址列伸縮與真實電容觸控微噪訊，單元測試（Node
  環境，無 DOM/視窗）無法模擬，需要 e2e（DevTools 裝置模擬）或實機 iPad Safari 驗收（依 PLAN
  的測試策略，這類項目本來就列為「真機人工」/e2e 驗收，不在 `npm test` 範圍內）。
- 8px 死區是經驗值（取自回饋中「未滑動超過 8px」的驗收描述），未針對不同裝置像素密度調整。
