## 交接筆記

依 `.bridge/reviews/verify-r2.md` 的兩個 FAIL 項目修正，都只動 `js/ui/editor.js`：

1. **AC-15**（觸控垂直畫線／拖曳被 `pointercancel` 中斷）：`onPointerDown` 呼叫 `hooks.renderBoard()`（`board.innerHTML = ...`）後，手指最初命中的節點會脫離 DOM，之後同一指的 `touchmove` 依 W3C 規範仍固定派發給該（已孤立的）節點，不會冒泡到 `#board`，所以綁在 `#board` 上的 `touchmove` 監聽器永遠收不到事件、`preventDefault()` 叫不到，瀏覽器就在約 15px 後判定為捲動並發 `pointercancel`。
   修法：新增 `bindTouchTarget(e)`／`unbindTouchTarget(e)`，在 `onPointerDown` 最開頭（任何 `renderBoard()` 之前）把同一份 `onTouchMove` 也掛到當下 `e.target` 上（用 `pointerId → target` 的 `Map` 追蹤），`endDrag` 時解除綁定。這樣即使節點被 `innerHTML` 換掉，瀏覽器派發給該孤立節點的 `touchmove` 仍會觸發 `onTouchMove`，`state.drag` 有值時照常 `preventDefault()`。
2. **AC-18**（雙指縮放在 `max-height` 留白的場地上錨點水平偏移；垂直平移同樣受 AC-15 同一個根因影響，已隨上面的修法一起解決）：`pinchMove()` 原本用 `board.getBoundingClientRect()` 線性換算 client → 場地座標，但 `#board` 觸及 CSS `max-height` 時 SVG 的 `preserveAspectRatio="xMidYMid meet"` 會在外框內置中縮放，實際繪製寬度小於 `rect.width`（左右留白），線性換算沒扣掉留白就會讓雙指縮放的錨點偏移。
   修法：改用 `ptRaw(clientX, clientY)`（`board.createSVGPoint()` + `getScreenCTM().inverse()`），在 `renderBoard()` 更新 `viewBox` 之前，用同一份 CTM 同時換算上一幀中心點 `drag.lastCenter` 與這一幀中心點，`getScreenCTM()` 本身就會處理 `preserveAspectRatio` 的留白偏移，兩者也落在同一個座標系快照下，不會跨幀亂跑。
