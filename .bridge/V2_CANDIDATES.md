# v2 候選需求

這份是**尚未核准**的候選清單，不屬於目前鎖定的 SPEC（v1 的非目標明訂「不新增匯出格式」）。
等 v1 驗收結案後，執行 `/elicit` 開 v2 時，從這裡挑選、排序，寫成 AC。
也請一併參考 `.bridge/使用感想.md`（例如同一步驟內依序移動、在動畫中停下來加註解）。

## 背景（2026-11-09 與使用者討論）

- 使用者想要「會動的圖」，主要用途是**交給學校的 PDF 電子檔**。
- PDF 本身播不了動畫：插入 GIF 只會留下第一格；嵌入影片或用 JavaScript 翻頁只有電腦版 Acrobat 會播，Chrome、Edge、iPad、Google 雲端硬碟預覽都不會播。
- 所以採用「靜態圖為主、動畫連結為輔」：PDF 正文放的靜態圖本身就要看得懂，動畫用連結或 QR code 補充。

## C1. 匯出 GIF 動畫

- 把步驟間的動畫匯出成 GIF，可以貼進簡報、Word、LINE，或上傳到雲端硬碟，把連結放進 PDF。
- 技術可行性：`js/ui/player.js` 的 `animFrame()` 本來就依時間組出每一格的 SVG 字串。抽成純函式 `frameSVG(doc, t)` 後，播放和匯出共用；每一格沿用 `js/ui/exporter.js` 的 SVG → canvas 流程，再用小型 GIF 編碼器（例如 gifenc，ESM，不用建置步驟）編碼。
- 選 GIF 而不是影片：到處都能自動播放；影片在 Word 不能貼，iPad 和電腦錄出的格式也不一樣。
- 訪談時要決定：步驟範圍（全部，或從第幾步到第幾步）、速度（沿用 0.5×／1×／2×？）、要不要循環播放、要不要保留步驟字幕、解析度與檔案大小上限、iPad 上的匯出時間。

## C2. 靜態圖加「移動軌跡」

- 匯出 PNG 時，用殘影和虛線標出人和球從上一步的哪裡移到哪裡，讓靜態圖也看得出跑位。這是給 PDF 正文用的。
- 技術可行性：`js/core/anim.js` 的 `planTransition()` 已經算出每個物件的起點、終點，以及沿哪條箭頭移動。
- 訪談時要決定：軌跡畫在「全部步驟」的每一格裡，還是另外輸出一張「總覽圖」；殘影的樣式；能不能關掉。

## C3. 分享連結＋QR code（打開就自動播放）

- 網站替單一份教案產生網址和 QR code，老師貼進 PDF，讀者點開或掃碼後直接播放動畫。
- 現況：網站還沒有單一教案的網址（共享區沒有個別範本的連結），要另外做路由和播放模式。
- 已排除的作法：把整份教案資料塞進網址（網址太長，QR code 太密、掃不出來）。
- 訪談時要決定：存在哪裡（Firebase，要不要登入才能產生）；要不要「不公開、只有拿到連結的人能看」；連結的有效期限與刪除方式；Firestore 規則與額度。

## C4. 匯出圖的圖例只列出圖上有用到的線條

- 使用者回饋（2026-11-09）：匯出圖的圖例固定列出「跑動、傳球、運球」，游泳圖根本用不到傳球、運球。
- 改法：`js/core/exportsvg.js:43` 的圖例目前寫死三種線條。改成只列出這次匯出的步驟裡實際出現的 `run`／`pass`／`dribble`；三種都沒用到時，整列圖例和它佔的高度都不要畫。
- 為什麼放到 v2：v1 的 AC-5 要求匯出圖「與舊版相同」，這是會改變輸出的行為變更。
- 改完要更新 `tests/unit/export.golden.test.js` 的 golden 比對，並補「只用跑動線」「沒有線條」的測試。

## 建議順序（尚未定案）

先做 C1（開發量小，搭配「上傳到雲端硬碟再貼連結」就能用），C2 和 C3 視需要放進同一版或之後再做。
