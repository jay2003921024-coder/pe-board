# 腳本／CLI／自動化專案：要釐清的事與常見盲點

## 通常要問（若無法推論）
- 怎麼觸發：手動執行 / 排程（cron）/ 檔案變動觸發 / 被其他程式呼叫
- 輸入是什麼：檔案（格式？）、API、資料夾、標準輸入
- 輸出到哪：檔案、終端機、通知、寫回某個服務
- 在哪裡跑：只有自己這台電腦（哪個作業系統？）/ 伺服器 / 給別人用

## 常見盲點（列進假設表）
- 重複執行安全嗎？（冪等性：跑兩次會不會產生重複資料）
- 處理到一半失敗：可以續跑嗎？會不會留下半成品？
- 錯誤輸入：檔案不存在、格式錯誤、空檔案
- 資料量：10 筆和 10 萬筆的差別（速度、記憶體）
- 會不會刪除或覆寫原始資料？是否需要先 dry-run？
- 憑證、API key 怎麼放（不能寫死在程式裡）
- 要不要記錄 log？

## 適合做原型的部分
指令的用法與參數（`--help` 長什麼樣）、輸出格式、錯誤訊息的寫法。用 `demo.txt` 模擬一次執行的終端機畫面。

## AC 範例
- AC-n：Given 輸入資料夾有 3 個 CSV，When 執行 `tool merge ./in -o out.csv`，Then out.csv 包含所有列且只有一列標題
- AC-n：Given 同樣的輸入，When 連續執行兩次，Then 輸出內容相同，沒有重複列
- AC-n：Given 輸入檔不存在，When 執行，Then 以非 0 結束碼退出，並印出可理解的錯誤訊息
